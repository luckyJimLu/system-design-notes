# 第 7 章：在分布式系统中设计唯一 ID 生成器

## 简介
本章解决了为分布式系统设计**独特的 ID 生成器**的挑战。由于可扩展性和同步挑战，传统的自动增量密钥不适合分布式环境。重点是创建满足以下要求的唯一、可排序、64 位数字 ID：
- ID 必须**唯一**并且**按日期排序**。
- ID 必须适合 **64 位**。
- 系统应**每秒生成超过 10,000 个 ID**。

---

## 第 1 步：了解问题
### 基本要求
- ID 必须是唯一的数字且应适合 64 位。
- ID 随时间增加，但不严格按 `+1` 增加。
- ID 应可按日期排序。
- 系统必须处理高吞吐量（10,000 ID/秒）。

---

## 第 2 步：高级设计选项
### 1. 多主复制
- **方法：** 使用带有步长增量的数据库 `auto_increment`（例如，对于 k 个服务器使用 `+k`）。

    <p align="left">
    <img src="./images/multi-master.png"  alt="Multi Master" width="400">
    </p>

- **缺点：**
  - 难以跨数据中心扩展。
  - ID 并不总是随着时间而增加。
  - 添加/删除服务器时出现扩展问题。

### 2.UUID（通用唯一标识符）
- **方法：**
    - 使用 UUID 在每个服务器上独立生成 128 位唯一标识符。
    - UUID可以独立生成，无需服务器之间协调

        <p align="left">
        <img src="./images/uuid.png"  alt="UUID generator" width="600">
        </p>

- **优点：**
  - 服务器之间不需要协调。
  - 通过 Web 服务器轻松扩展。
- **缺点：**
  - 超过 64 位要求。
  - ID 不能按时间排序，并且可能是非数字。


### 3. 票务服务器
- **方法：** 使用集中式数据库服务器来递增和分配 ID。

    <p align="left">
    <img src="./images/ticket-server.png"  alt="UUID generator" width="500">
    </p>

- **优点：**
  - 对于小型系统来说易于实施。
  - 生成数字 ID。
- **缺点：**
  - 单点故障。
  - 多服务器设置中的同步挑战。

### 4.Twitter雪花法
- **方法：**

    <div style="margin-left:3rem">
      <img src="./images/twitter-snowflake.png"  alt="Snowflake approach" width="500">
    </div>
    <div style="margin-left:3rem">
      <img src="./images/snowflake-id-breakdown.png"  alt="Snowflake ID breakdow" width="500">
    </div>

    - 将 ID 分为几个部分以确保唯一性和可扩展性。
    - **符号位（1 位）：** 始终为 `0`，可能区分有符号数和无符号数。
    - **时间戳（41 位）：** 自自定义纪元以来的毫秒数（Twitter 的默认值为 `1288834974657`，相当于 2010 年 11 月 4 日，01:42:54 UTC）。确保 ID 是按时间排序的。
    - **数据中心 ID（5 位）：** 最多标识 `2^5 = 32` 数据中心。
    - **机器 ID（5 位）：** 标识每个数据中心内最多 `2^5 = 32` 的机器。
    - **序列号（12 位）：** 跟踪同一毫秒内机器上生成的 ID，每毫秒最多支持 `2^12 = 4096` ID。该序列每毫秒重置为 `0`。



- **优点：**
    - **可扩展性：** 每秒跨多个服务器处理 10,000 多个 ID。
    - **时间顺序：** 确保 ID 可按时间排序。
    - **去中心化：**无单点故障。


## 第 4 步：其他注意事项
### 1. 时钟同步
- **挑战：** ID 生成假设服务器之间的时钟同步。
- **解决方案：** 使用**网络时间协议 (NTP)** 来最大程度地减少漂移。

### 2. 节长调整
- 根据用例调整部分大小（例如，更少的序列位、更多的时间戳位）。

### 3、高可用
- ID 生成器是关键任务，必须具有容错能力。
- 考虑冗余和故障转移机制。
